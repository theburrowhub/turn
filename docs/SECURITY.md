# Turn's threat model

Turn runs coding agents on the user's machine and opens a local HTTP port that
turns incoming JSON into state the user acts on. Both halves of that sentence are
security surfaces, and they point in opposite directions:

- an agent Turn launched can run arbitrary commands, so **everything it produces
  is untrusted input**;
- a user looks at Turn's sidebar to decide what to attend to, so **anything Turn
  displays is load-bearing**.

This document says what Turn trusts, what it does not, what is mitigated and how,
and what is knowingly accepted for the MVP with the reasoning. It is written to be
falsifiable: nearly every claim below has a test named after it, and the tests are
phrased as the attack rather than the happy path, so a change that removes a
defence fails a test that says what was lost.

---

## 1. What an attacker wants

| Asset | Why it is worth attacking |
| --- | --- |
| The user's attention | Turn decides what the user looks at next. Forging "your agent is waiting for you" is a way to make someone open a session and act inside it. |
| An approval | The one moment a user grants an agent something dangerous. Misrepresenting *what* is being approved is the highest-value attack in the product. |
| A pty | Anything that can write to a pty can type into the user's shell and into a running agent's prompt. |
| Credentials | A developer machine has `ANTHROPIC_API_KEY`, `GITHUB_TOKEN`, cloud credentials and session cookies in its environment, and agents read files. |
| The daemon's liveness | The daemon holds every live session. A crash is data loss; a hang is worse, because the sessions are still running and nothing is being reported. |

## 2. Trust boundaries

**Trusted.** The user. The daemon process itself. The SQLite store's contents (it
is Turn's own file, written by Turn). Anything the user typed into Turn's UI.

**Untrusted — this is the important list.**

1. **Everything an agent writes to its stdout.** Titles, screen contents, spinner
   text. It is generated by a model steered by whatever it has been reading: a
   repository, a web page, a pasted stack trace.
2. **Everything inside a hook payload.** A valid token proves *which session*
   posted, and nothing about the contents. `tool_input.command`, `prompt`,
   `last_assistant_message`, `agent_type`, `session_id` are all model-authored
   strings.
3. **Every other process on the machine, including the agents Turn launched.** An
   agent can run `curl`, read `/proc`, and open loopback ports.
4. **The environment `turn-hook` inherits.** It runs inside the agent's process
   tree, so a repository's `direnv` or task runner has a say in it.

**The boundary Turn does not defend, and cannot.** Anything running as the same
user. The daemon's control socket is `0600`, which stops other accounts, but any
process running as the user can connect to it and drive Turn completely — write to
ptys, kill sessions, read scrollback. Given that, a same-user attacker does not
need to forge hook events; they can ask the daemon directly. Defending against
same-user code requires OS-level sandboxing of each agent, which is a product
decision, not a patch. §7 says what follows from this.

## 3. Surfaces, and what defends them

### 3.1 The hook server (`turn-agents/src/server.rs`)

| Property | How |
| --- | --- |
| Not reachable off the machine | Binds `127.0.0.1:0` explicitly, never `0.0.0.0`. |
| Not reachable without the secret | One route, `POST /hook/{token}`. The token is per **node**, minted from two v4 UUIDs — 244 bits from the OS CSPRNG (`uuid`'s v4 reads `getrandom`, not a seeded userspace PRNG) — and is not derived from anything an agent already knows. Guessing is not a threat at this size; there is deliberately no lockout, because a lockout would be a way for one process to deny hooks to every session. |
| No enumeration oracle | Every rejected token gets the same answer: `404`, empty body. Wrong length, wrong case, one character off and the real token truncated are indistinguishable. The lookup is a `HashMap` get, so it is not constant-time — over loopback, against 244 bits, with the same secret usable directly by any same-user process, that is not the weak link. |
| Never answers with a decision | Claude Code's hook protocol allows a response that allows or denies a tool call. Turn always replies `200` with an empty body. `turn-hook` reads the response only far enough to know it landed, and would not carry a decision if one arrived. |
| Bounded memory per request | `DefaultBodyLimit::max(256 KiB)`, enforced before the body is buffered, for both a declared `Content-Length` and an endless `Transfer-Encoding: chunked` stream. |
| Bounded stack | `serde_json` refuses beyond ~128 levels of nesting, so a payload built to recurse is a parse error rather than a stack overflow. Turn also never walks a payload recursively beyond the parse. |
| Bounded connections | 128 at a time (`Limits::max_connections`). Further connections are closed on arrival and counted in `HookStats::overloaded`. Without this, a local process could exhaust the daemon's file descriptors and break the parts of it that have nothing to do with hooks. |
| No stalled connections | Each connection carries a 30-second **idle** deadline, reset by any byte in either direction, so a socket that connects and says nothing — or a `Content-Length` that lies — is dropped and counted in `HookStats::timed_out`. It is an idle timeout and not a lifetime, and it is deliberately generous: closing an idle keep-alive connection races a client that reuses it at that instant, and losing that race loses a real event, whereas a lingering socket costs one of 128 slots. Claude Code gives a hook three seconds, so nothing legitimate comes close. |
| One slow client cannot stall another | Every connection is its own task, and the handler never awaits anything downstream: it does a hash lookup, a parse, and a `try_send`. |
| A slow daemon costs events, not agents | The event channel is bounded at 1024 and `try_send` drops on a full channel, counted in `HookStats::dropped`. Blocking would apply backpressure to every agent on the machine. |

### 3.2 Agent output rendered as UI (`turn-pty/src/buffer.rs`)

An agent controls its own stdout, and parts of that reach native chrome: session
titles, tree labels, thumbnails, notifications, log lines.

- `is_display_safe` is the single policy for what may appear in text a human
  reads. It removes control characters (C0 **and** C1, so both `ESC` and the
  8-bit `CSI` at U+009B), bidirectional formatting (U+202A–U+202E, the isolates,
  LRM/RLM), the line and paragraph separators U+2028/U+2029 — which are *not*
  `char::is_control` and will inject a second line into a log record — and the
  invisible families: zero-width spaces and joiners, word joiner, BOM,
  interlinear annotation, and the Unicode tag characters U+E0000–U+E007F, which
  can carry a whole hidden ASCII sentence inside a label that renders as "build".
- `sanitise_label` consumes whole escape sequences rather than dropping the `ESC`
  alone, because `ESC [ 2 J` would otherwise leave a readable `[2J` behind.
- Titles are sanitised and capped to 200 characters **at the callback**, not on
  the way out: the parser buffers an OSC payload without a bound of its own, so a
  megabyte-long title would otherwise be retained per pane.
- Screen rows get the same filter in `snapshot()`, so a thumbnail cannot render an
  agent's output backwards.
- OSC 52 is refused in **both** directions and counted: writes
  (`blocked_clipboard_writes`) and reads (`blocked_clipboard_reads`), the second
  being the exfiltration direction — answering it would put whatever the user last
  copied into the process's stdin. A process-requested window resize is refused
  too. These refusals are written out explicitly rather than inherited from
  `vt100::Callbacks`'s empty defaults, so a dependency bump that gave one of those
  defaults a real implementation cannot silently turn agent stdout into clipboard
  access.
- Invalid UTF-8 becomes U+FFFD (`from_utf8_lossy`). Lone surrogates cannot exist
  in a Rust `String`; in JSON they are a parse error.
- Replay uses the parser's `contents_formatted()`, not the raw byte ring, so
  re-attaching a pane cannot re-emit the original OSC 52 or title sequences into
  the UI's terminal.

### 3.3 Payload fields rendered as UI (`turn-agents/src/text.rs`)

The same filter, applied on the other input path. Every string an adapter lifts
out of a payload goes through `text::excerpt` — whitespace collapsed first, as a
substitution, so a newline stays a word boundary instead of welding two words
together — before it can reach an event, a notification or a log line.

Two special cases:

- **Commands are filtered but never shortened** (`MAX_COMMAND_CHARS`, 4 KiB).
  Truncating a command for display would hide its own tail, and the tail is where
  `&& rm -rf /` lives. The one-line `summary` *is* an excerpt; the approval UI is
  responsible for showing the full `command` field before the user decides.
- **Identifiers are validated, not filtered** (`text::identifier`). An agent
  reports its own session id, Turn stores it, and resuming later runs
  `claude --resume <that id>`. An id is therefore accepted only if it matches
  `[A-Za-z0-9._:-]{1,128}` and does not begin with `-`. Anything else is refused
  outright rather than repaired, because a partly rewritten id would resume the
  wrong conversation.

### 3.4 The launch path

- **No shell, anywhere.** `PtyProcess::spawn` builds a `CommandBuilder` with an
  explicit argv and never passes a command line to `sh`. Adapters pass the user's
  command through untouched and append their own arguments as separate argv
  entries. `no_adapter_wraps_the_users_command_in_a_shell` fails if that changes.
  The one deliberate exception is `turnd`'s workspace start-up command, which is
  `$SHELL -c <command>` **by design** — it is a shell command the user wrote (see
  §8 for what that requires of template handling).
- **Generated configuration is generated, not concatenated.** Claude Code's
  settings document is built with `serde_json`, so escaping is structural. Codex's
  inline TOML is built by hand — the shape is a single command-line value — and
  everything interpolated goes through `toml_escape`.
- **Selection cannot be tricked into claiming more than it knows.** A shell is
  never treated as an agent, even as `sh -c 'claude'`; an unrecognised command
  becomes a plain terminal that makes no claims.

### 3.5 Secrets (`turn-store/src/redact.rs`)

Two rules, because either alone leaks:

1. **By key.** The value of any key whose name contains `TOKEN`, `KEY`, `SECRET`,
   `PASSWORD`, `CREDENTIAL`, `COOKIE` or `AUTH` is replaced, case-insensitively,
   at any depth, in environments, layouts, templates and JSON documents. The key
   survives, because "GITHUB_TOKEN was set" is what explains an authentication
   failure after a restore.
2. **By shape.** `redact_secrets` replaces anything recognisable as a credential
   wherever it appears — `sk-ant-…`, `ghp_…`, `github_pat_…`, `glpat-…`, `xoxb-…`,
   `AKIA…`, `AIza…`, JWTs, and PEM private-key blocks as blocks. This exists
   because the most common way a credential reaches Turn is *unlabelled*: inside a
   command an agent asks to run (`curl -H "Authorization: Bearer …"`) or inside a
   prompt the user pasted. Matching is on issuer-assigned prefixes at a word
   boundary, not on entropy: an entropy rule would eat commit hashes, paths and
   UUIDs and make the log useless. It will miss a credential with no distinctive
   shape, so it is a net under rule 1, not a replacement.

Both rules run on the raw payload **and** on the serialised event kind, which is
where a permission request keeps its command and a turn start keeps a prompt
excerpt.

The retained payload keeps its control characters on purpose. Serialising it as
JSON turns `ESC` into the six readable characters `` rather than a live
escape sequence, so fidelity for "a stray escape byte was sent" costs nothing —
that is what the field is for. Bidirectional and invisible formatting is the
exception, because JSON does *not* escape it and it would stay live in any event
inspector: `strip_misleading` removes exactly that class and nothing else, which is
why a stored event is entirely `is_display_safe` end to end.

Adapters also minimise before storing (`text::raw_for_storage`): members that
carry bulk content rather than state — `content`, `old_string`, `new_string`,
`patch`, `diff`, `stdout`, … — are dropped, and the whole payload is capped at
8 KiB. A `Write` permission request contains the entire file the agent is about to
write; copying that into the event log would duplicate the user's source, and any
credential in it, into a second file with a different lifetime, in exchange for
nothing Turn renders.

### 3.6 `turn-hook`

- Only `http://`, and **only a loopback destination**. The helper's environment is
  the agent's environment, so `TURN_HOOK_URL` is not entirely Turn's to control; a
  non-loopback destination would make Turn's own helper a tidy exfiltration
  channel for payloads containing prompts and replies. `localhost` is accepted as
  a literal name, and names are never resolved-then-checked, so no DNS answer gets
  a vote.
- No failure ever becomes a non-zero exit or unsolicited stderr. A broken helper
  must not break the user's agent session.
- Debug output masks the token: a debug line lands in the user's terminal and in
  the agent's own transcript.
- Reads are capped at 256 KiB from stdin and 64 bytes from the response.

## 4. Product invariants, defended as security properties

These are in `crates/turn-agents/tests/invariants.rs` and are meant to fail loudly
if a later change is careless.

| Invariant | Test |
| --- | --- |
| A heuristic can badge a session but never move focus | `nothing_the_heuristic_infers_can_ever_move_the_users_focus` — checks every screen the heuristic reacts to, not one example, and asserts the test would be meaningless if it stopped reacting |
| The confidence cap is wired, not just declared | `a_heuristic_source_cannot_promote_itself_however_it_is_constructed` |
| A guessed confirmation is not a permission Turn offers to resolve | `a_guessed_confirmation_is_never_presented_as_a_permission_turn_can_resolve` |
| Turn never auto-approves | `no_payload_can_make_an_adapter_say_a_permission_was_allowed`, plus `the_response_never_carries_a_permission_decision` and `a_response_that_tries_to_decide_something_is_read_and_ignored` |
| Turn never executes what it read | `a_payload_that_asks_turn_to_run_something_only_ever_produces_a_description` |
| Parent/child links are Confirmed only from a tool report | `subagent_hierarchy_only_ever_comes_from_an_explicit_report` |
| An agent cannot choose a command-line flag | `an_agent_cannot_choose_a_command_line_flag_by_naming_its_own_session` |
| No shell in the launch path | `no_adapter_wraps_the_users_command_in_a_shell` |

Turn never relaunches anything: `SessionRepo::load_for_restore` downgrades every
stored `Alive` to `Orphaned`, and the UI offers rather than acts.

## 5. Fixed in this audit

Ranked by severity, worst first.

1. **The per-session token was published in the process table.** Codex's
   `notify` array carried `--url http://127.0.0.1:PORT/hook/<token>`, so the token
   sat in `codex`'s argv. `/proc/<pid>/cmdline` is world-readable on Linux, which
   made every Codex session's token available to any account on the machine with
   one `ps` — the exact forgery the token exists to prevent. The URL now travels
   only in `TURN_HOOK_URL`. The same fix was applied to Claude Code's helper
   transport.
2. **The generated settings file was world-readable.** `claude-hooks.json`
   contains the hook URL, and `std::fs::write` left it at the umask's mercy —
   `0644` in a `0755` directory on a stock machine, with the path visible in argv.
   Now `0600` in a `0700` directory, narrowed again on rewrite.
3. **An agent could choose its own command-line flag.** `session_id`,
   `thread-id` and `agent_id` come from the payload, are stored as `external_id`,
   and are passed back as `claude --resume <external_id>`. A reported id of
   `--dangerously-skip-permissions` would therefore have been handed to the tool
   as a flag on the user's behalf. Now validated by `text::identifier`.
4. **Credentials reached the database under innocent keys.** The serialised event
   kind was stored unredacted, so `AgentPermissionRequired.command` and
   `AgentTurnStarted.prompt_excerpt` — a command with a bearer token in it, a
   prompt with a pasted key — were written verbatim. Redaction now covers the kind
   as well as the raw payload, and matches credential shapes as well as key names.
5. **File contents reached the database.** A `Write` permission request carries
   the whole file in `tool_input.content` (confirmed in the captured fixture), and
   the whole payload was stored. Bulk members are now dropped and the payload is
   capped.
6. **Escape sequences and bidi overrides reached UI text.** `excerpt` collapsed
   whitespace but passed `ESC`, `BEL` and U+202E through, so an agent-authored
   command, message or model name could carry an OSC 52 clipboard write or reverse
   its own rendering next to an approval button. Titles were sanitised but the
   filter missed bidi controls, U+2028/U+2029 and Unicode tag characters, and
   screen rows were not filtered at all. All of it now goes through
   `is_display_safe`.
7. **An unterminated title could be retained without bound.** `vte` buffers an
   OSC payload in a `Vec` with no cap when built with `std`, and Turn stored
   whatever came out of it per pane. The retained title is now sanitised and
   capped at the callback. The parser's own transient buffer is upstream and
   unbounded; see §7.
8. **The hook server had no connection cap and no timeouts.** A local process
   could hold connections open indefinitely, or promise a `Content-Length` it
   never sent, costing the daemon descriptors and tasks. Now capped, reaped and
   counted.
9. **The clipboard-read direction of OSC 52 was refused only by inheriting a
   default.** Now refused explicitly and counted.
10. **`turn-hook` would post to any host.** Now loopback only.
11. **`turn-hook` printed the token in a debug failure.** Now masked.
12. **The risk badge was defeated by reordering flags.** `rm -r -f x`,
    `rm --recursive --force x` and `git push origin main --force` were all rated
    Medium while `rm -rf x` was High. A warning that misses the same command
    spelled differently teaches the user to trust its absence.

## 6. Verified as safe, and why

Stated so the next audit does not re-litigate them.

- **Token entropy and generation.** 244 bits from `getrandom`. Not derived from
  the node id, not a counter, unique per node — a test asserts 32 concurrent
  registrations produce 32 distinct tokens.
- **Cross-session isolation of accepted events.** A token maps to exactly one
  `(session_id, node_id)`; the payload cannot name a different session. One
  hundred concurrent posts from a hundred nodes all arrive attributed to their own
  session.
- **Revocation.** `unregister` takes effect immediately; a revoked token is
  refused like any forgery.
- **A dropped receiver, a full channel, an unparsable body.** All answer `200`,
  because a registered agent has done nothing wrong and telling it otherwise risks
  Claude Code deciding Turn's hook is broken.
- **The daemon's control socket.** `0600`, asserted by a test in `turnd`.
- **The parsed screen never contains escape sequences.** They are interpreted by
  `vt100`, and replay is regenerated rather than replayed from raw bytes.
- **DNS rebinding against the hook port.** A browser can send a cross-origin
  `POST` to a loopback port, but there is no route that does anything without the
  token, and the token is not obtainable from a web page.
- **`transcript_path` and `cwd` in stored payloads.** Accepted deliberately, and
  it is not a leak Turn introduces: the store already keeps every session's `cwd`
  and command line because restoring the desk is the product. `transcript_path`
  reveals the user's home directory and project name to a file that lives in the
  user's own data directory. What makes it acceptable is that the DB is not more
  exposed than the paths it describes — which is exactly what §8's first item is
  about.

## 7. Knowingly accepted for the MVP

**A compromised agent can impersonate any session.** An agent Turn launched runs
as the user, so it can read another session's settings file, another process's
environment, or simply connect to the daemon's `0600` control socket and drive
Turn directly. The per-node token therefore buys separation between *accounts*,
and honesty about which node reported what, but it is not a wall between two
agents on one machine. Accepting this is a straight consequence of the product:
Turn's job is to run the user's agents with the user's privileges. Anything better
requires sandboxing each agent (a per-agent uid, a container, or macOS's sandbox
profiles), which is a product decision with its own cost — agents need the user's
`PATH`, credential helpers and ssh agent to work at all.

**A determined local process can deny hook delivery.** With connections capped, an
attacker who reconnects continuously can occupy the slots. Nothing at this layer
prevents that, and a lockout would only give them a cheaper way to do it. What is
defended is the daemon's integrity: bounded descriptors, bounded memory, no
crash, no hang, no loss of unrelated state. A process that can do this can also
just `SIGSTOP` the daemon.

**The token travels in a URL path.** Claude Code's HTTP hook configuration takes a
URL and a timeout; there is no documented header field, so the secret has to be in
the URL. It is consequently in the settings file (now `0600`), and may appear in
Claude Code's own logs, which Turn does not control.

**`vte` buffers an unterminated OSC string without a bound.** With the `std`
feature — which `vt100` enables — the OSC buffer is a `Vec`, and the const-generic
cap is only available under `no_std`. A hostile process can therefore make the
parser hold a large transient allocation for one pane until the sequence ends.
Turn's retention is capped, the pty byte ring is capped, and the fix belongs
upstream; sniffing writes for unterminated OSC introducers before handing them to
the parser would be a fragile second parser.

**The risk badge is advisory and evadable.** `eval "$(printf '\x72m -rf /')"` will
not be caught, and cannot be. This is acceptable *only* because nothing is gated
on the rating: `Low` produces a quieter colour, never an approval. If it ever
decides whether to *ask*, this reasoning stops holding.

**Prompt injection into an agent is out of scope.** A repository can contain text
that steers an agent. Turn's contribution is to refuse to be the mechanism: it
never executes what an agent said, never approves on the user's behalf, and never
lets agent-authored text misrepresent itself in the UI.

## 8. Reported, not fixed

Outside the files this audit was scoped to change. Each has a specific fix.

1. **The database file is world-readable.** `turn-store/src/location.rs` —
   measured on macOS with `umask 022`: `turn.db` at `0644` inside a data directory
   at `0755`. It contains commands, working directories, prompt excerpts and
   assistant-message excerpts. `~/Library` is `0700` on macOS so the exposure is
   currently indirect there, but `~/.local/share` is commonly `0755` on Linux.
   *Fix:* `ensure_dir` should create with mode `0700`, and `Store::open_at` should
   `set_permissions(0o600)` on the file after opening. Worth a test asserting both,
   next to the existing `secrets_never_reach_the_disk.rs`.
2. **`turnd` renders payload-authored strings as labels.** `core/events/tree.rs`
   assigns `node.title = agent_type` and `agent.external_id = agent_id` straight
   from the event. Those are now filtered and validated in the adapters, so the
   daemon is safe today — but the daemon should not depend on that. Any *other*
   process-derived string it puts in a label (a `ProcessSpawnedChild.command` read
   from the process table, for instance) should go through
   `turn_pty::sanitise_label`, which is exported for exactly this.
3. **`turnd` runs the workspace start-up command through a shell.**
   `core/spawn.rs` builds `$SHELL -c <command>`, which is correct for a
   user-authored init command and a command-injection vector for anything that is
   not. *Requirement:* templates and workspaces must only ever come from the user
   or the store — never auto-loaded from a file inside a repository — and the UI
   must show the command before it runs. If repository-provided templates are ever
   wanted, that decision needs its own review.
4. **The UI must show the full command before an approval.** `AgentPermissionRequired`
   carries both a one-line `summary` (an excerpt) and the full `command`. An
   approval banner that shows only the summary can be made to hide the dangerous
   half of a long command.
5. **Codex's hook `command` value is run through a shell** — confirmed live and
   documented in `codex.rs`, which POSIX single-quotes the helper path and *then*
   TOML-escapes it. That order is load-bearing and easy to lose: the TOML parser
   unwraps its layer first, and the shell sees what is left. Any future value
   interpolated into that config needs both layers, in that order. Reviewed and
   correct as written; noted here because it is the one place in the launch path
   where a shell is genuinely involved.
6. **`HookStats::overloaded` and `timed_out` deserve to be surfaced.** A non-zero
   `refused` or `overloaded` means something on this machine is posting to Turn
   without a valid token or opening sockets it does not use. That is exactly the
   kind of thing a user should be able to see.

## 9. If you are changing this code

- Anything that reaches a label, a notification, a log line or a stored field and
  came from a process or a payload goes through `turn_pty::sanitise_label` or
  `turn_agents::text`. There is no third way to do it.
- Anything that reaches an argv position and came from a payload goes through
  `text::identifier`.
- Never widen `EventSource::PtyHeuristic`'s confidence cap. It is the difference
  between a badge and a stolen focus.
- Never add a response body to the hook endpoint.
- Bounds are not optional: a new buffer that a process can grow needs a cap and a
  counter for what it dropped.
