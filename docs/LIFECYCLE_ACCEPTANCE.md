# Command Palette and lifecycle acceptance

Run from the repository root without opening the desktop application:

```sh
make lifecycle-acceptance
```

The target exercises the same typed protocol, daemon persistence, hierarchy actions and native-window
policy used by Turn.

| Requirement | Reproducible evidence |
| --- | --- |
| Quick Preview and Open Node are real hierarchy actions | `palette_hierarchy_commands_reuse_the_typed_tree_actions` |
| Search and typed Attention/Running/Failed/Archived filters are palette commands | the `Command::ALL` and keymap completeness tests plus `palette_hierarchy_commands_reuse_the_typed_tree_actions` |
| Pane movement, process signals and Template application remain discoverable commands | the keymap completeness suite and existing pane, terminal and Template suites |
| Workspace/Session rename edits the current value | `session_lifecycle_commands_use_real_values_and_typed_operations`; the old generated `"(renamed)"` path does not exist |
| Duplicate, archive and restore are separate real operations | the request catalogue plus the Desk command tests |
| Favorite and pin persist independently | `favourite_and_pin_are_durable_independent_session_choices` |
| Session ordering uses the daemon-owned `move_tree_node` operation | the hierarchy movement suite; Move Session Up/Down routes through that same action |
| Closing the Turn window preserves processes by default | `close_turn_defaults_to_preserving_every_running_process` and `close_turn_defaults_to_closing_only_the_window` |
| Stop-all/per-Session exit waits for daemon answers | `TurnApp` keeps the native close cancelled until every typed `close_session` request settles |
| Closing a view, detaching, stopping a Process, ending a Session and archiving remain distinct | the lifecycle, terminal and lease suites selected by this target |
| Atajos are configurable and discoverable | `every_command_is_bound_exactly_once_and_appears_in_the_palette` and the shortcut-settings suite |

Pause/resume is intentionally not exposed as a command yet. Turn can own a PTY while the semantic Agent is
a descendant process, and a restored process may be observable without being signalable. An OS-level
`SIGSTOP`/`SIGCONT` button would therefore sometimes pause the wrong runtime while retaining a checkout
lease. The honest current operations are interrupt, stop, end Session, and explicit relaunch/resume where
the adapter proves it is resumable. There is no disabled or placeholder pause control.

Destructive actions still use their contextual confirmation. Duplicate, favorite, pin, filter, preview and
open actions are non-destructive and execute immediately. If a palette command lacks a valid typed target,
the status bar says exactly what selection or state is required.

## Accepted successor lifecycle matrix

ADR-064/065/066 extend the post-v0.1 lifecycle target. These rows are acceptance obligations, not claims that
`make lifecycle-acceptance` proves them today:

| Requirement | Required successor evidence |
| --- | --- |
| Foreground Session activation needs no second action when safe | One Session selection emits one idempotent `activate_session`, restores/attaches and may start the exact bounded eligible saved-runtime descriptor set—or one configured default Shell when empty—only from a current fully preflighted plan. Retry does not double-start. Stale authority, target/account/cwd/command drift, an ambiguous survivor, missing containment, a permission or unsafe input owner launches nothing and presents one exact recovery action. Selecting a child, resource, history result or ended Session never activates it. |
| External WorkItems retain explicit authorities | Local create starts at backlog and Turn-authority commands follow the local transition table. Fresh external-authority observations may jump mapped state with source provenance. External create reserves Node/WorkItem/CreationId before dispatch and requires correlation; import/bind/detach, source/sync/presence/projection/mutation/conflict reducers are closed. Every write freezes its exact binding/source/mapping/item revisions, and reconcile performs lookup only. Projection/source-config actions never mutate provider work. |
| Provider-native Jobs are not Flow recurrence | Fixtures preserve one stable Job identity and ordered iteration identities across provider/daemon disconnect. Exact `list` and `get` produce independent bounded revisioned observations; `create`, `update`, `pause`, `resume`, `run_now`, `cancel_iteration` and `delete_job` produce independent receipts. Create reserves one exact Session/Group-owned Job Node+CreationId before dispatch; uncertain create/run-now reconciles only its correlation. Prepared creation cancel and local hide-activity/forget/restore have zero provider effect; destructive provider deletion is separately labelled and fenced. |
| Conversation inventory, adoption and resume remain separate | Search and bounded history pages launch nothing and cannot prove absence from partial coverage. Adopt creates one stopped Node and installation-wide exact ConversationKey ownership without provider input. Resume performs a fresh foreground target/account/model/cwd/containment preflight and creates at most one new RuntimeAttempt. Similarity never binds ownership. |
| WebPreview and Browser have different continuity | Restoring an inert WebPreview Resource loads no URL or script. Explicit WebPreview load crosses its own durable intent before HTTP; lost evidence is lookup-only and never refetched, while body/renderer state is never restorable presentation state. Restoring a Browser Node restores only inert metadata; renderer, history and ephemeral partition bytes do not survive and restore does not reload or navigate. WebPreview load plus Browser creation and navigation/history/reload/stop cross separately bounded durable intents before effect. Destroy/End maps every prepared/no-effect intent to cancellation and every fetching/dispatching/reconcile/created survivor to exact rehome or semantic recovery before row removal. It revokes preview authority immediately; proved-quiescent allocations release and possibly live fetch allocations plus charges transfer to bounded recovery cleanup until quiescence. Browser partition bytes clear, and neither path claims server-side deletion. |
| Title read and rename do not share authority | Provider title read is a read-only capability. Rename is a separately advertised, expected-revision/idempotent operation whose requested title becomes effective only after correlated provider evidence; ambiguous or rate-limited outcomes reconcile rather than invent success. |
| Typed permission response is exact; remote response is narrow | Fresh supported typed enables distinct local-desktop and acknowledged-grant remote operations. Remote submit atomically consumes the immutable grant before provider effect; all submit/revoke/expiry/reconnect/revision/crash outcomes retain a recoverable dispatch/evidence receipt and reconciliation never resends. Typed blocks raw bytes; only fresh supported verified-local-PTY enables daemon-encoded desktop fallback. Other fact states and remote/voice/hook/background surfaces fail closed. |
| Account activity is profile-scoped and tri-state | Context windows, quota windows and the bounded activity inbox keep exact provider/AccountProfile/target identity plus independent source, coverage and freshness. Missing, partial, stale, rate-limited and failed reads never become zero usage, zero remaining or authoritative empty history. |
| Recursive Groups and CheckoutScope have separate lifecycle | A depth-128 same-Session Group forest survives reverse-order restore and atomic subtree operations; self/indirect/concurrent cycles and corrupt/depth overflow refuse without a partial tree. Group promote/delete never stops work. CheckoutScope provisioning/active/missing/conflicted/unbinding/removing/reconcile-required/unbound/removed remains separate from optional Group binding proposed/current/refused/stale/unbound; binding unbind changes no scope/worktree, scope unbind terminalises the binding and retains the worktree, remove alone may delete it, adopted defaults to keep, and presentation move never rewrites cwd. |
| WorkspaceOnboarding is a resumable saga | One preassigned onboarding id passes the closed prepared/running-phase/cancel-requested/reconcile-required/terminal machine and records every frozen phase receipt. Crash/cancel at each path/directory/target/fetch/checkout/commit/cleanup phase reconciles only the exact path/repository/remote identity, repeats no ambiguous effect and never publishes implicitly. |
| Model endpoint route state is independent | Draft/validating/active/degraded/invalid/retired/deleted transitions use exact target/profile/credential generation. Late discovery cannot reactivate or overwrite a changed route; missing/revoked secrets or trust change launch nothing. A proved same-conversation switch preserves the AgentInstance and creates exactly one new RuntimeAttempt/configuration receipt; refusal, failure or uncertainty leaves the prior attempt current, while continuity that cannot be proved offers an explicit Branch/new instance. |
| Resource observation never implies lifecycle control | Complete/partial/gapped/unavailable/stale and measured-empty/unmeasured ResourceInventory updates alter only telemetry. Current, closed-owner and unmatched live rows remain visible. Terminate requires a fresh separate foreground receipt over exact target+handle+process-start+observation revision; error/PID reuse/late remote response changes no runtime. |
| Notification delivery has its own retry state | One NotificationDeliveryId follows exactly `eligible → held_present|queued|superseded|expired`, `held_present → queued|superseded|expired`, `queued → submitted|superseded|expired`, `submitted → accepted|failed_retryable|failed_terminal|superseded|expired` and `failed_retryable → queued|failed_terminal|superseded|expired`, with a bounded attempt count. Retry, expiry, revocation, endpoint failure, gateway acceptance and live-status end never acknowledge/read/respond/resolve Attention; an end/tombstone prevents late resurrection. |
| Local display naming is not provider/runtime lifecycle | Follow-source facts and generated proposals can change only an unpinned local label at the current Node/Group revision. Manual pin survives reconnect, attempt replacement and provider title change; apply/unpin/provider rename are separate operations and emit no launch, input or lifecycle transition. |

A full remote GUI is a revisioned WorkSurface client with identical semantics for the registry-allowed
non-destructive lifecycle operations and input leases it shares with a local GUI. Destructive lifecycle remains
`LocalDesktopForegroundAuthority`-only. A headless status client and a companion are bounded projections with
closed action allowlists; neither may inherit arbitrary lifecycle or PTY authority merely because the full GUI supports it.

## ADR-067 bulk restart, Eco and preserved-store lifecycle

| Capability | Required lifecycle oracle |
| --- | --- |
| Bulk idle restart (`ACP-LIF-010`) | A≤256-row preview freezes Workspace inventory/policy/Attention/interaction/input revisions and daemon-derives exact eligible/excluded reasons. Only exact Idle, local, stoppable, resumable, child/background/recovery/input/Attention-free, non-primary candidates run, one at a time. Every candidate has a preassigned canonical restart id and exactly one restarted/skipped/failed/reconcile receipt. Cancel fences before the next item; crashes at every boundary use lookup only; final summary accounts once for every preview row and never substitutes a changed agent. |
| Eco hibernation (`ACP-LIF-011`) | Disabled means zero exits. Enabled admits only continuously Idle≥configured≥15m, off-screen, local, resumable, child/recurrence/background/prompt/Attention/input-free evidence and dispatches≤2/minute. A durable intent precedes typed adapter hibernate, preserves the same Session/multiplexer/scrollback and never injects shell text. Selection/Attention/Flow demand automatically persists wake and reattaches without a user start action. Ambiguous exit/wake never repeats; wake failure creates one actionable recovery demand without losing continuity. |
| Browser Memory Saver (`ACP-RUN-020`) | Disabled means zero discard. Enabled requires one exact current revision continuously hidden≥5m and excludes loading, audible, agent-controlled, popup/download/print/action and unsubmitted form/POST states at the final reducer edge. `discarded` appears only after renderer/partition quiescence and keeps only safe public URL+policy identity with history-loss truth. Same-daemon selection creates exactly one fresh navigation intent when still allowed or one typed bottom-status block; restore/reconnect/restart, policy drift and possible-effect crash never auto-load or duplicate. |
| PTY capacity/remediation (`ACP-RUN-021`) | One-minute target sampling, two-minute freshness and target-generation loss transition exact observations without claiming healthy zero. Elevated/critical status and deduplicated Attention precede capacity refusal, but pressure never Ends/kills/detaches/reaps a live or unowned process. A reviewed remediation follows prepared→dispatching→kernel-applied→persisting→verifying and exact applied/rolled-back/failed/partial recovery outcomes; cancel is pre-dispatch and crash reconciliation performs no second privileged effect. |
| Corrupt store (`ACP-SAF-019`) | Parse/checksum/schema failure, descriptor race, alias, disk-full, permission and fsync crash points yield either the exact original untouched/read-only or one verified atomic quarantine before any default save. Recover/start-fresh/export/discard intents are individually idempotent and no success/timeout/dismiss/expiry erases quarantine. Capacity N+1 preserves bytes and refuses state publication. |
| Cross-client change (`ACP-SAF-020`) | Two authenticated clients race create, field update, self-echo, gap, disconnect and reconnect. One receipt creates one canonical Session/Node; distinct changes apply in stream order or resnapshot, same operation echo applies once, disjoint presentation fields merge only by declared revisions, conflicts stay visible and locally dirty drafts survive. No file watcher, full-store JSON replacement or runtime restart participates. |
